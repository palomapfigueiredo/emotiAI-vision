EmotiAI Vision — Guia explicado de forma simples

Objetivo deste guia: explicar como o EmotiAI Vision funciona com palavras simples, exemplos do dia a dia e passos curtos. Os nomes dos arquivos e os exemplos de código continuam disponíveis para quem quiser estudar a parte técnica.

Início

Como o EmotiAI Vision observa movimentos em uma sala?

Imagine uma sala de aula e uma câmera apontada para as pessoas. O EmotiAI Vision é um projeto que analisa imagens da câmera para perceber alguns movimentos do corpo, como levantar a mão.

Ele faz isso em várias etapas. Primeiro, recebe a imagem. Depois, procura pontos do corpo, acompanha onde eles estão e verifica se um braço parece estar levantado. Por fim, reúne os resultados em números que ajudam a entender o que aconteceu durante aquele período.

Importante: o sistema observa movimentos que podem ser vistos na imagem. Ele não sabe o que alguém está pensando, se está feliz, se está prestando atenção ou se aprendeu a matéria. Levantar a mão é um movimento observável; sentimentos e pensamentos não podem ser descobertos apenas por esse movimento.

Três cuidados importantes

Não tenta descobrir quem é a pessoa
O sistema usa pontos do corpo, como ombros, cotovelos e punhos. Ele não precisa reconhecer o rosto para analisar esses movimentos.

Não guarda vídeos ou fotos no computador
De acordo com o projeto, os quadros da câmera são analisados durante a execução e não são salvos como arquivos de vídeo ou imagem. O programa reúne informações numéricas para mostrar um resumo.

Os códigos de acompanhamento são temporários
O sistema pode usar nomes como track_1 e track_2 para diferenciar as pessoas enquanto está funcionando. Esses códigos servem para o programa acompanhar os movimentos; não são nomes reais. Eles deixam de existir quando a execução termina.

Como o sistema funciona

O caminho da imagem: oito etapas

Pense em uma linha de montagem. Um objeto passa por diferentes estações e cada estação faz uma tarefa. No EmotiAI Vision, a imagem também passa por etapas: cada parte do programa faz um trabalho específico e entrega o resultado para a próxima.

  1. Captura: a câmera entrega uma imagem ao programa.
  2. Detecção de pose: o sistema procura pontos do corpo, como ombros, cotovelos e punhos.
  3. Rastreamento: o programa tenta descobrir quais pontos de uma imagem correspondem à mesma pessoa na imagem seguinte.
  4. Análise de postura: o programa verifica se os pontos indicam que um braço está levantado.
  5. Eventos: quando algo muda, como um braço subir ou descer, o sistema registra essa mudança.
  6. Resumo das métricas: depois de um intervalo, o programa junta os registros e calcula números.
  7. Visualização de depuração: durante os testes, o programa pode desenhar os pontos e as linhas sobre a imagem.
  8. Loop principal: é a parte que organiza a ordem das tarefas e faz o processo se repetir.

Cada etapa tem uma responsabilidade. Isso facilita entender, testar e corrigir o projeto sem precisar colocar tudo em um único arquivo.

Passo 1 — Captura de vídeo

1. A câmera entrega a imagem

Arquivo: camera/capture.py

Tudo começa com a câmera. Ela captura o que está à sua frente e entrega as imagens ao programa. Cada imagem recebida é chamada de frame — pense nela como uma fotografia muito rápida dentro de um vídeo.

A classe CameraCapture é a parte do código responsável por conversar com a câmera. Ela configura detalhes como largura, altura, quantidade de imagens analisadas por segundo e rotação.

Um exemplo simples

Imagine que você está folheando um livro de desenhos animados. Cada página mostra o personagem em uma posição um pouquinho diferente. Quando as páginas passam rapidamente, parece que ele está se mexendo. A câmera entrega imagens de forma parecida: muitas imagens em sequência.

E se a câmera falhar?

O programa verifica se conseguiu receber uma imagem. Se a leitura falhar ou a câmera estiver desconectada, ele informa que houve um problema em vez de continuar como se tivesse recebido uma imagem válida.

Por que o código libera a câmera?

Quando o programa termina, a câmera precisa ser liberada para que outros aplicativos possam usá-la. O código usa um recurso do Python que ajuda a garantir essa liberação mesmo se ocorrer um erro durante a execução.

Configurações da câmera

O arquivo camera/config.py reúne as opções da câmera, como resolução e rotação. O arquivo principal fornece essas configurações. Assim, a parte que captura a imagem não precisa saber como o restante do sistema analisa os movimentos: ela só precisa entregar as imagens corretamente.

Passo 2 — Detecção de pose

2. O sistema procura pontos do corpo

Arquivo: detection/pose_detector.py

Agora que a imagem chegou, o sistema precisa encontrar partes do corpo. Para isso, o projeto usa o MediaPipe Pose Landmarker, uma ferramenta que estima pontos do corpo em uma imagem.

Esses pontos são chamados de landmarks. Entre eles estão os ombros, os cotovelos, os punhos, os quadris e pontos das pernas. O modelo usado pelo projeto pode identificar até 33 pontos para cada pose detectada.

Imagine um boneco de palitos

Pense em um desenho de boneco feito com bolinhas e linhas. Cada bolinha marca uma parte do corpo, e cada linha mostra a ligação entre duas partes. O sistema usa pontos estimados de maneira parecida para entender a posição do corpo.

Esses pontos são estimativas feitas pelo computador. Se uma parte estiver escondida, fora da imagem ou difícil de enxergar, o sistema pode ter menos certeza sobre sua posição.

Por que existem nomes para os pontos?

O arquivo detection/pose_landmarks.py dá nomes aos pontos, como left_shoulder (ombro esquerdo) e right_wrist (punho direito). Isso é mais fácil de entender do que lembrar números, como “ponto 15” ou “ponto 16”.

O código também verifica se os pontos parecem confiáveis. De forma simples, é como perguntar: “Consigo enxergar esse ponto com segurança suficiente para usá-lo?”

Por que analisar o vídeo em sequência?

O programa recebe imagens continuamente, e não apenas uma fotografia isolada. Por isso, o sistema informa o momento de cada imagem ao MediaPipe. Isso ajuda a ferramenta a lidar com a sequência de imagens de maneira adequada.

Lembre-se: encontrar pontos do corpo não é o mesmo que reconhecer a identidade de uma pessoa. O objetivo desta etapa é estimar a posição do corpo, não descobrir o nome de quem aparece na câmera.

Passo 3 — Rastreamento

3. Como o sistema acompanha a mesma pessoa?

Arquivo: tracking/tracker.py

Imagine que duas pessoas estejam na frente da câmera. Em uma imagem, o sistema encontra dois conjuntos de pontos. Na imagem seguinte, ele encontra os pontos novamente. Como pode tentar saber qual conjunto corresponde a cada pessoa?

É para isso que serve o rastreamento (tracking). O programa compara a posição dos pontos entre imagens consecutivas. Neste projeto, ele usa principalmente a proximidade entre os centros dos ombros.

Um exemplo

Na primeira imagem, o conjunto de pontos A está do lado esquerdo e o conjunto B está do lado direito. Na próxima imagem, o sistema procura conjuntos em posições próximas para tentar continuar acompanhando cada um.

Ele pode criar identificadores temporários, como track_1 e track_2. Pense neles como etiquetas em dois objetos: ajudam o programa a não misturar os movimentos durante a execução, mas não revelam a identidade real das pessoas.

E se alguém ficar escondido por um instante?

Uma pessoa pode passar atrás de outra ou sair parcialmente da imagem. O programa permite que um acompanhamento fique sem atualização por alguns frames antes de considerar que aquela pessoa desapareceu.

Se o sistema não conseguir relacionar uma pose nova com um acompanhamento existente, poderá criar um novo identificador. Como a comparação é feita pela posição, o rastreamento pode se confundir em algumas situações — por exemplo, quando pessoas se cruzam ou ficam muito próximas.

Por que essa etapa é importante?

Sem o rastreamento, o programa teria mais dificuldade para entender que os pontos vistos agora podem pertencer à mesma pessoa que apareceu na imagem anterior. Essa etapa ajuda a organizar os movimentos ao longo do tempo.

Passo 4 — Análise de postura

4. Como o sistema percebe um braço levantado?

Arquivos: analysis/arm_detection.py e analysis/posture_detection.py

O sistema já encontrou os pontos do corpo e está tentando acompanhá-los. Agora ele verifica uma pergunta específica: a posição dos pontos indica que um braço está levantado?

Para responder, o programa compara a altura de pontos como o punho, o ombro, o cotovelo e, quando está visível, o quadril.

A regra em palavras simples

Em uma imagem de computador, os pontos mais altos costumam ter um valor vertical menor. Por isso, para verificar se a mão está acima do ombro, o código compara as posições do punho e do ombro. Ele também verifica a posição do cotovelo em relação ao quadril.

O programa usa uma pequena margem para evitar que uma diferença mínima ou um tremor faça o braço mudar de estado por engano.

Se o quadril não estiver visível, o sistema pode usar uma regra mais simples, baseada no punho e no ombro. Nesse caso, ele tem menos informação para fazer a análise.

Por que não decidir com apenas uma imagem?

Imagine que você levante a mão e mexa um pouquinho o braço. A posição estimada pode variar de uma imagem para outra. Se o programa reagisse a cada pequena mudança, poderia dizer que o braço subiu e desceu várias vezes, mesmo sem isso ter acontecido de verdade.

Para reduzir esse problema, o projeto espera que a mesma situação apareça em vários frames seguidos. A configuração padrão exige 5 frames consecutivos antes de confirmar a mudança.

E se o sistema não conseguir enxergar bem o braço?

Em vez de assumir automaticamente que o braço está abaixado, o programa pode tratar a situação como desconhecida quando os pontos não são confiáveis. Assim, evita registrar uma mudança apenas porque alguém ficou escondido ou saiu parcialmente da imagem.

Importante: essa regra identifica uma posição estimada do braço. Ela não consegue saber por que a pessoa levantou a mão nem se ela deseja fazer uma pergunta.

Passo 5 — Eventos

5. Como o sistema registra o que aconteceu?

Arquivo: events/event.py

Quando algo importante muda, o programa cria um evento. Um evento é como uma anotação curta em um caderno: registra o que aconteceu e em que momento.

Alguns exemplos de eventos que o projeto reconhece são:

  • Uma pessoa foi detectada.
  • Uma pessoa deixou de ser acompanhada.
  • O braço esquerdo foi reconhecido como levantado.
  • O braço direito foi reconhecido como levantado.
  • Os dois braços foram reconhecidos como levantados.

Cada evento pode guardar informações como o tipo de mudança, o identificador temporário da pessoa, o nível de confiança e o momento em que ocorreu.

O evento é um resumo de uma mudança

O programa não precisa escrever todos os detalhes de todas as imagens para registrar que um braço passou de abaixado para levantado. Ele registra a mudança relevante.

O EventManager organiza a criação desses registros e escreve informações no log do programa. Ele não mantém um histórico completo e permanente de todos os eventos; os registros são encaminhados para a etapa que prepara os resumos.

Passo 6 — Métricas agregadas

6. De muitos acontecimentos para um resumo

Arquivos: analysis/aggregator.py e analysis/participation.py

Até aqui, o sistema recebeu muitas imagens e pode ter identificado várias mudanças. Ler cada acontecimento separadamente seria trabalhoso. Por isso, o projeto reúne os resultados em intervalos de tempo.

O tempo padrão de cada intervalo é 10 segundos. Esse período é chamado de janela de agregação.

Pense em uma contagem de brincadeira

Imagine que, durante dez segundos, três pessoas diferentes levantem a mão. Em vez de mostrar cada detalhe para sempre, o programa prepara um resumo com números sobre o que observou naquele intervalo.

O resumo pode incluir:

  • Média de pessoas: a quantidade média de pessoas detectadas durante o intervalo.
  • Máximo de pessoas: o maior número de pessoas detectadas em um momento daquele intervalo.
  • Pessoas que participaram: quantas pessoas diferentes foram contadas como participantes pelas regras do sistema.
  • Eventos de braços levantados: quantas vezes foram registrados eventos desse tipo.
  • Taxa de participação: uma proporção calculada a partir das pessoas participantes e da média de pessoas detectadas.

O que a taxa de participação quer dizer?

A taxa usa informações observáveis, como quantas pessoas diferentes levantaram o braço durante o intervalo e a média de pessoas detectadas. Ela não mede sentimentos, satisfação, atenção ou aprendizado.

Por exemplo, uma pessoa pode estar prestando muita atenção sem levantar a mão. Outra pode levantar a mão por vários motivos. O sistema não sabe o motivo: ele só analisa movimentos que consegue observar.

O projeto reúne esses valores em um resumo no formato JSON, que é uma maneira organizada de guardar informações usando nomes e valores. Por exemplo, um campo pode ter o nome people_max e guardar o maior número de pessoas detectadas naquele intervalo.

Atenção: os números dependem da qualidade da imagem e das estimativas do sistema. Eles devem ser interpretados como estimativas dos movimentos observados, não como uma avaliação completa das pessoas.

Passo 7 — Visualização de depuração

7. Por que aparecem linhas e pontos sobre o corpo?

Arquivo: debug/renderer.py

Durante o desenvolvimento, é útil ver o que o sistema está detectando. A parte chamada DebugRenderer desenha pontos e linhas sobre a imagem da câmera.

As bolinhas indicam os pontos estimados do corpo, enquanto as linhas ligam esses pontos para formar uma espécie de esqueleto. Assim, quem está testando o projeto consegue observar se o sistema encontrou os ombros, os cotovelos e os punhos nas posições esperadas.

Para que serve essa visualização?

Imagine tentar montar um quebra-cabeça sem olhar a imagem que está formando. Seria difícil saber se as peças estão no lugar certo. A visualização de depuração funciona como uma ajuda visual para conferir o resultado do sistema.

Essa visualização é voltada para testes e desenvolvimento. O projeto permite desligá-la usando a configuração debug_mode=False. Quando ela está desligada, o esqueleto deixa de ser desenhado na tela pela etapa de depuração.

Passo 8 — O loop principal

8. Como tudo funciona junto?

Arquivo: main.py

Cada etapa tem uma tarefa, mas alguém precisa organizar a ordem em que elas acontecem. Esse é o trabalho do arquivo main.py, que funciona como o maestro de uma orquestra.

Ele coordena o processo:

  1. Recebe uma imagem da câmera.
  2. Envia a imagem para encontrar os pontos do corpo.
  3. Tenta acompanhar as pessoas entre as imagens.
  4. Analisa a posição dos braços.
  5. Registra as mudanças importantes.
  6. Atualiza e reúne as métricas.
  7. Mostra a visualização de depuração, se ela estiver ativada.
  8. Repete o processo enquanto o programa estiver funcionando.

Por que não analisar todas as imagens?

A câmera pode entregar muitas imagens por segundo. Analisar cada uma delas pode exigir mais trabalho do computador do que o necessário para este projeto.

Por isso, o programa tem uma configuração que controla quantas imagens serão processadas por segundo. Por exemplo, a câmera pode fornecer 30 imagens por segundo, enquanto o sistema analisa 10. Nesse caso, ele não precisa fazer a análise completa de todas as imagens recebidas.

Isso ajuda a controlar o uso dos recursos do computador, sem confundir a velocidade da câmera com a velocidade de análise do sistema.

Configurações do projeto

O que é possível ajustar?

Arquivo: config/settings.py

As configurações são como os controles de um jogo: permitem mudar alguns comportamentos do programa sem precisar reescrever toda a lógica.

Configuração Valor padrão O que significa
frame_width / frame_height 1280 × 720 A largura e a altura solicitadas para a imagem da câmera.
rotation 180° A rotação aplicada à imagem.
max_poses 10 O número máximo de poses que o sistema tenta detectar em uma imagem.
min_landmark_confidence 0,5 O nível mínimo de confiança usado para considerar um ponto válido, conforme a implementação do projeto.
target_processing_fps 10 A quantidade aproximada de imagens que o sistema pretende analisar por segundo.
required_consecutive_frames 5 Quantos frames seguidos são exigidos para confirmar uma mudança de postura.
aggregation_window_seconds 10 segundos A duração de cada intervalo usado para montar um resumo.
tracker_max_distance 0,18 A distância máxima permitida para relacionar uma pose nova a um acompanhamento existente.
tracker_max_missed_frames 8 Quantos frames podem passar sem atualização antes de o acompanhamento ser considerado perdido.

Os valores padrão são os definidos no guia do projeto. Dependendo da câmera, da iluminação e da posição das pessoas, pode ser necessário testar configurações diferentes.

Como executar o projeto

Vamos colocar o EmotiAI Vision para funcionar?

Para executar o projeto, é necessário ter o ambiente preparado e instalar as bibliotecas usadas pelo código. As bibliotecas são conjuntos de ferramentas que ajudam o programa a realizar tarefas específicas.

O guia do projeto lista estas dependências:

  • mediapipe — ajuda a estimar os pontos do corpo.
  • opencv-python — ajuda a acessar e trabalhar com imagens da câmera.
  • numpy — oferece ferramentas para trabalhar com dados numéricos.

Comandos de execução

No terminal, entre na pasta do projeto e execute o programa usando o Python do ambiente virtual configurado:

cd app/computacional-vision
./venv/bin/python main.py

O comando acima corresponde ao exemplo do projeto e pressupõe que o ambiente virtual esteja nesse caminho e que as dependências já estejam instaladas. Em outros sistemas operacionais, o caminho para o Python do ambiente virtual pode ser diferente.

Se a janela de depuração estiver aberta, o guia do projeto indica que a tecla Q pode ser usada para encerrar essa janela.

O que acontece quando o programa termina?

Os identificadores temporários, como track_1 e track_2, são usados durante a execução. Quando o programa termina, eles deixam de ser mantidos para aquela sessão.

Para lembrar

O EmotiAI Vision segue uma sequência de tarefas: recebe imagens, estima pontos do corpo, tenta acompanhar as pessoas, verifica movimentos específicos e reúne os resultados em números.

A principal ideia é contar movimentos que podem ser observados, como levantar um braço. O sistema não descobre pensamentos, emoções, intenções ou o quanto alguém aprendeu.
